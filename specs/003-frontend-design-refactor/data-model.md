# UI View-Model and State Inventory

This feature introduces no persistent entities, migrations, or API changes. The
following existing view models remain the source of dynamic content:

| View model | Used by | Required dynamic values |
|---|---|---|
| `PublicEvent` / event detail | Home, detail, checkout | id, title, poster, schedule, venue, synopsis, availability, price |
| Catalog result/detail | Organizer create | external id, title, image/category, provenance |
| Reservation/payment state | Checkout | quantity, expiry, approved/declined/expired outcome |
| Customer ticket | My Tickets, detail, shared ticket | event, owner, status, issued time, secure QR/share state |
| Auth session | Login and protected routes | JWT, expiry, role |
| Organizer event | Organizer list | status, capacity, sold/available, operational fields |
| Gate validation result | Gate states | `VALID`, `INVALID`, `ALREADY_USED`, `WRONG_EVENT`, attempted time |

## UI state rules

- Loading states render while the corresponding request has no resolved value.
- Empty states render only for successful responses with no records.
- API/network/authorization errors remain actionable and never fabricate records.
- Payment and gate result states are transient/rendered states of existing routes.
- Camera denial/unavailability preserves manual credential entry.
- Secure QR/share values remain generated by existing backend/API behavior.
